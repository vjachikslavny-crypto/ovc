# Стабилизация этапов 0–2

## Контракт блоков и редактор

`app.agent.block_models` — общий контракт note CRUD, AI draft и commit. `data.source="ai"`
сохраняется для всех видов блоков. Legacy `doc.kind="doc"` сохраняет исходный формат;
он не переименовывается в DOCX. Нормализация добавляет стандартные значения/aliases,
но не выбрасывает неизвестные данные: неподдерживаемая запись остаётся в БД, запись через
API получает ошибку валидации. Повреждённый JSON не выдаётся как пустая заметка.
Редактирование названия видео также соответствует канонической схеме.

Редактор хранит состояния clean/dirty/saving/save_failed/offline. Снимки копируются, PATCH
отправляются последовательно, подтверждение старого снимка не очищает новую правку.
Ошибка сохраняет pending; три автоматических повтора используют задержку, далее доступен
ручной повтор. Возврат сети запускает повтор. `beforeunload` предупреждает о реально
неподтверждённых изменениях; `pagehide` оставляет локальную копию. Переходы редактора/обычные
ссылки сначала ожидают подтверждённого сохранения. Браузер может прервать запрос при закрытии:
гарантия здесь обеспечивается восстановлением черновика, а не обещанием доставки запроса.

Черновики: localStorage, ключ `ovc:draft:<проверенный user id>:<note id>:<writer uuid>`, без токенов.
Вкладки имеют отдельные копии; при восстановлении выбирается самая свежая, остальные
сохраняются. Копия другой вкладки удаляется лишь если не менялась после чтения.
При повторном входе владельца черновики восстанавливаются. Если серверная версия отличается,
редактор предлагает отдельную восстановленную заметку и сохраняет обе версии; отмена
оставляет копию на месте. Ошибка/квота localStorage явно предупреждает не закрывать страницу.
Это приватные данные браузерного профиля, не зашифрованное автономное хранилище.

GET после тегов/связей обновляет только метаданные, без замены текста/DOM редактора.
AI-коммит сначала сохраняет текст и приостанавливает PATCH, затем объединяет серверные
изменения с появившимися локальными правками. Конфликт одного блока не разрешается молча.
При неопределённом результате коммита повторная отправка AI отключается: сначала GET и
сверка результата. Это защита от дублирования после потерянного ответа.

PATCH `/api/notes/{id}` поддерживает необязательный `If-Match: "<updatedAt>"` из последнего
GET/PATCH. Редактор передаёт его: устаревший снимок получает 409 и остаётся локальным черновиком.
Без заголовка старые desktop/sync-клиенты сохраняют прежний контракт. CRDT и общее
редактирование одной заметки этим не реализуются.

## Доступ и сессии

`app.core.ownership` требует точного владельца заметки/файла во всех режимах. Файл с note_id
проверяет также владельца заметки. Оба конца связи, AI-контекст, поиск и граф ограничены
текущим пользователем. Orphan-записи обычными запросами не присваиваются.

**Изменения, которые заметит пользователь:**

- `AUTH_MODE=none` показывает только данные специального dev-user, а не все аккаунты базы.
  Чтобы открыть свои данные, используйте соответствующий режим и войдите в свой аккаунт.
- Supabase не связывается с локальной записью лишь по совпадению email. Правильная существующая
  привязка работает; конфликт или непривязанный локальный аккаунт с тем же email даёт 409.
  Новый UI связывания аккаунтов не добавлялся; проверка владения обеими учётными записями
  перед отдельным административным связыванием обязательна.
- Общие настройки цветов/названий графа из `group_preferences` сохранены, но больше не
  применяются ко всем аккаунтам. Новые настройки записываются в `user_group_preferences`
  с ключом `(user_id, key)`; автоматического угадывания владельца старых настроек нет.
- Старые неоднозначные bridge-сессии в Supabase-only требуют повторного входа.

Выход из аккаунта также сначала ждёт сохранения: credentials не удаляются до подтверждения PATCH.

Local-механизмы регистрации/входа/verify/смены пароля/refresh доступны только в local/both.
Supabase bridge доступен только в supabase/both. Refresh хранит провайдера: local-cookie
не даёт доступ к данным в supabase-only. Явный ошибочный Authorization не подменяется
другой cookie-личностью. Dev fallback не может выбрать обычную запись с именем dev-user.

Ошибки входа и lockout фиксируются транзакцией до HTTP-ошибки. Naive SQLite datetime
нормализуется в UTC. Refresh-rotation сериализована (`BEGIN IMMEDIATE` SQLite, row lock
PostgreSQL); повтор rotated-токена отзывает сессии пользователя, и отзыв коммитится до 401.
Logout возвращает именно ответ, очищающий cookies.

Для небезопасных HTTP-методов с auth-cookies действует CSRF-проверка. Bearer-запросы не
переключаются на refresh-cookie при отказе. Refresh/logout дополнительно требуют CSRF.
Secure строго соответствует настройке, без понижения по Host/X-Forwarded-Proto;
SameSite=None разрешён только с Secure. Access-cookie остаётся доступной JS, как требуется
нынешнему frontend; refresh-cookie — HttpOnly. Полная переделка token storage не входит в этап.

## Настройки и sync-ограничения

Публичный режим определяется `PUBLIC_MODE=true`, `APP_ENV=production` или `PUBLIC_BASE_URL`.
С `AUTH_MODE=none` запуск блокируется; единственный явный опасный обход —
`ALLOW_UNSAFE_PUBLIC_NO_AUTH=true`, с предупреждением. Публичный Cloudflare launcher
передаёт `PUBLIC_MODE` дочернему процессу. В production Secure по умолчанию включён;
для localhost HTTP явно используйте `COOKIE_SECURE=false` и SameSite=Lax.

Файловый proxy после 404 сначала проверяет владельца/ссылку в принадлежащей пользователю
заметке. Он использует только токен самого запроса, никогда общий sync bearer и никогда
анонимный fallback. Remote-only файлы без пользовательского access-токена могут потребовать
повторного входа. Redirect с удалённого файлового сервера не обходится автоматически.

Протокол sync не менялся. Добавлены лишь проверки изоляции: фоновый токен должен разрешаться
в конкретного активного локального пользователя; иначе worker отключается с логом. Ручной
trigger использует токен вызвавшего пользователя. Ни worker, ни ручной вызов не забирают
outbox с NULL/чужим владельцем и не переприсваивают чужие заметки при pull. AUTH_MODE=none
не считается подтверждением remote identity. Legacy-очередь требует отдельного разбора.

## Проверка

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -m pytest -q
node --test tests/note_save.test.mjs
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python -B tests/manual_editor_smoke.py
.venv/bin/python -B scripts/audit_local_data.py
```

Pytest принудительно использует временные БД/хранилище через `tests/conftest.py`.
Upload-тесты больше не запускают миграции рабочей базы при импорте. Browser smoke использует
установленный Playwright/Chromium, отдельную БД и временный localhost-порт, завершает сервер
после проверки. Ответ модели подменён тестовой SSE-фикстурой; commit/PATCH/GET — настоящие.
Живые Supabase, PostgreSQL, Cloudflare и Tauri в этих проверках не используются.
